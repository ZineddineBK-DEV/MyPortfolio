Automation

Turning infrastructure work into a web form

The data center and lab projects all have the same shape: something that used to be a ticket and a person with vCenter access becomes a request in a web application, handled by an API, reported back in real time. It is ordinary web development — with a very unforgiving backend.

  • Authenticate — the application signs into vSphere with its own service account, and every user action is checked against their role before anything is provisioned.
  • Request — creating a VM, cloning a template, taking a snapshot, powering a machine off: each becomes a validated API call with a defined input, not a free-text instruction.
  • Queue — provisioning is slow, so actions run as tracked jobs with a state machine instead of one HTTP request that might time out.
  • Act — the Node.js service calls the vSphere REST API, waits on the task, and records what happened and who asked for it.
  • Report — Socket.io pushes job progress and live metrics into the dashboard; MongoDB keeps the history that capacity questions get answered from.

Portal → API with job queue → vSphere REST API, with every action logged and pushed live to the dashboard.

The same pattern carries the IoT work: sensors publishing over MQTT into a Node.js service that stores history and pushes live readings to a dashboard. Different protocol, same architecture.
